# Quote catalogue review (the owner gate before any quote rule is written)

This document is the row-by-row review Decision 13 requires: the 29 rows of the quote catalogue (`docs/design/phase1-fixtures.md`) were typed **first**, from the design's rules and the fixture bytes, and the owner walks every row here **before Turn 1.6 writes any quote rule**. The agent that writes the rules (Turns 1.6/1.7) must not have seen these labels; the labels are frozen by the additions-only label ledger.

Every fixture here is tiny, synthetic and has exactly one purpose (the catalogue's “raw line or element the fact hinges on” column). **Owner:** put `ok` / `change` / `question` in the last cell of each row. For the 2026-10-05 **delegated** sign-off the 26 original rows are accepted as typed (see “Owner sign-off (delegated)” below); rows 27-29 were added afterwards and stay to be reviewed.

## How the labels were produced

By hand, from the design rules, **with no package, walker, HTML tree, text decoder or any library run over any fixture to produce a label**. The Phase 0 facts (`container.*`, `headers.fields`, `part.tree`, `part.regions`, `part.gaps`, `body.preamble_epilogue`, `decode.chain`, `body.content_sha256`), the live phase-1 facts (`body.text`, `body.html_spans`, `body.alternative_group`, `body.selection`) and the quote facts (`body.quote_boundaries`, `body.view_levels`) were typed by reading each fixture's bytes (a byte/offset listing) against the design documents. The L1 gate then compared the Phase 0 and live facts to the walker: **matched=1128, mismatched=0** (`python -m emailextract.evals`). The quote facts are reported `not_yet` (phase 1): no measurer exists until Turns 1.6/1.7, which is the point of typing them first.

Four rows are RAW byte literals (`tools/write_raw_fixtures.py`) because the bytes ARE the fact (a U+00A0 before each French label's colon, a lone `-- ` line whose trailing space a formatter would eat, a run of exactly sixty underscores, a headers-only message with a blank line and no body); the rest are generated by `tools/make_fixtures.py`'s own byte renderer.

This is a **delegated** sign-off, **not a row-by-row eyeball**. The owner delegated the review of
this catalogue to the reviewer's recommendation and took that recommendation verbatim: **all seven
open questions below are decided AS RECOMMENDED** (Q1-Q7), and **rows 1 to 26 are accepted as typed
except where a decision changes a typed value** (rows 23 and 24, the two marker-block spans; no
other row's typed value changes). The rule-writing turns (1.6/1.7) still must not read these labels.

## Open questions (numbered; all seven DECIDED by the delegated owner sign-off of 2026-10-05, as recommended)

1. **The span extent of a boundary.** Does an `On ... wrote:` or Outlook-flat boundary span only its marker line, or the whole quoted block? *Decided as recommended (2026-10-05):* the whole quoted block (rows 1, 6, 14, 15) — that is what a consumer that keeps new text needs. Typed into `labels.undetermined`.
2. **How several boundaries collapse to one view level.** With several boundaries (or per-line `>` depths that differ) `body.view_levels` still has one row per view. *Decided as recommended (2026-10-05):* the highest of any boundary's ordinal and its deepest per-line `>` depth (rows 2, 3, 12, 11); the design only says `level = ordinal` where a structural rule fired, else `level = prefix_depth`.
3. **A Gmail container wrapping an Outlook block.** Is the level 1 or 2? *Decided as recommended (2026-10-05):* one ordinal per view, level 1 (row 13, `mixed_origin_quote`).
4. **Does a forward banner suppress the flat block inside it?** Row 21 (`begin_forwarded_message`) types a forward boundary (level 0) and an outlook-flat boundary (level 1) for the block under the banner. *Decided as recommended (2026-10-05):* the banner is level 0 and does not suppress the flat block, which is still the sender's quoted prior words.
5. **The kind of `-----Original Message-----`.** Read as kind `forward` (level 0) by decision 3's grouping with the Begin-forwarded banner (row 22). *Decided as recommended (2026-10-05):* forward, but whether it is instead kind `quote` is not spelled out.
6. **The vendor-prefix gap is not yet emitted.** Row 26's named gap `body.html_quote_rule_gap` is expected but NOT asserted in `gaps.later`: the Turn-1.5 `htmltree` records that id only for an UNCLOSED quote container, while the design's trigger here is a class matching a vendor prefix family with no table row — a Turn 1.7 DOM rule. Asserting it now would be a live-gap mismatch. *Decided as recommended (2026-10-05):* Turn 1.7 adds the trigger and this row moves its gap into `gaps.later`.
7. **Where a signature / list-footer span ends.** After the marker line, or the whole block below it? Rows 23 and 24 type the marker lines only. *Decided as recommended (2026-10-05):* the marker block.
